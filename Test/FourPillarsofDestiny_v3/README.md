# 몽글토끼 사주 리포트 — 통합 기준 소스

개인 사주, 기간 운세, 자동 추천 궁합, 1:1 궁합, 그룹 관계를 한 화면 흐름에서 제공하는 Flask 기반 로컬 웹앱입니다. 사용자 화면은 전문 명리 데이터를 그대로 나열하기보다 **“나는 어떤 사람인가 → 상대는 어떤 사람인가 → 어디가 잘 맞고 어디서 부딪히는가 → 실제로 어떻게 맞춰갈 것인가”**를 먼저 보여주도록 구성합니다.

> 사주명리는 전통 해석 체계입니다. 과학적으로 검증된 사건 예측, 건강·투자 판단, 관계 성공 확률을 제공하는 서비스가 아닙니다.

## 적용 순서

기존 프로젝트를 업데이트하는 경우 **기존 `.env`와 `data/` 폴더는 보존**합니다. `data/`에는 이미 확인한 원국 원문과 실행시간 통계가 있으므로 삭제하면 다시 조회해야 할 수 있습니다.

### 전용 가상환경으로 실행

태양광 발전량 예측 프로그램을 비롯한 다른 Python 프로젝트와 패키지가 섞이지 않도록 이 프로젝트는 `.venv-fourpillars-v3`만 사용합니다. Windows에서는 아래 배치 파일을 실행하면 Python 3.10 기반 전용 환경 생성, 패키지 설치, Chromium 준비와 앱 실행까지 자동으로 처리합니다. 현재 셸에 다른 가상환경이 활성화되어 있어도 해당 환경을 사용하지 않습니다.

```bat
run_windows.bat
```

직접 명령을 실행할 때도 시스템 `python` 대신 전용 인터프리터를 사용합니다.

자동 테스트까지 실행하려면 개발 의존성을 한 번 설치합니다.

```bat
.venv-fourpillars-v3\Scripts\python.exe -m pip install -r requirements-dev.txt
```

```bash
# 1) 소스 교체 후 기존 원문을 현재 파서로 재구조화
.venv-fourpillars-v3\Scripts\python.exe reparse_cache.py

# 2) 정적 자산·핵심 로직 계약·문법 검수
.venv-fourpillars-v3\Scripts\python.exe verify_project.py

# 3) 자동 테스트
.venv-fourpillars-v3\Scripts\python.exe -m pytest -q

# 4) 실행
.venv-fourpillars-v3\Scripts\python.exe app.py
```

브라우저:

```text
http://127.0.0.1:8787/
```

로컬 통합 테스트 화면:

```text
http://127.0.0.1:8787/test
```

`/test`는 localhost에서만 열리며 실제 분석은 자동 시작하지 않습니다.

## 사용자 경험 원칙

- 첫 화면은 입력과 분석 범위를 빠르게 이해할 수 있게 구성합니다.
- 생년월일은 단일 입력칸을 기본으로 하고 숫자 8자리, 점·하이픈·슬래시 형식을 허용합니다.
- 출생시간 미상은 임의 시주를 만들지 않습니다.
- 대한민국 출생은 도시 입력을 요구하지 않고, 해외 출생만 국가·도시를 받습니다.
- 결과 첫 화면은 핵심 요약을 먼저 보여주고 전문 명리 근거는 접어서 제공합니다.
- 성격·직장·재물·관계·연애·학습 카드는 높이가 바뀌지 않으며, 선택한 내용은 카드 아래의 전체폭 패널에서 보여줍니다.
- 긴 해설은 `키워드 → 짧은 소제목 → 실제 상황 → 활용/소통 방법 → 명리 근거` 순으로 나눕니다.
- 원국 표의 표시 순서는 모든 화면에서 **시주 → 일주 → 월주 → 연주**로 고정합니다.
- 직장·프로젝트 그룹에는 애정 표현·배우자·데이트 등의 연애 문구를 사용하지 않습니다.

## 데이터와 계산 원칙

- 외부 원국 자료가 확인되면 해당 자료를 우선합니다.
- 같은 출생 조건의 외부 원국 자료가 한 번이라도 저장되어 있고 실제 일주를 재현할 수 있으면 **브라우저 재조회보다 기존 자료 재사용을 우선**합니다. 신강·신약·용신·대운 같은 선택적 세부 항목이 비어 있어도 자동 외부 재조회 사유로 사용하지 않습니다.
- LOVE와 FRIEND/WORK는 별도의 점수 축을 사용합니다.
- 점수와 순위는 Python 규칙 엔진만 계산하며 자연어 생성이 점수를 변경하지 않습니다.
- 자동 추천은 실제 달력상 존재하는 날짜·12시진을 모두 로컬 구조로 1차 탐색합니다.
- 포스텔러에서만 확정되는 신강·신약·용신을 로컬 계산만으로 단정하지 않기 위해 **연도별 상위 후보를 세부 원국으로 재확인**한 뒤 정밀 재채점합니다. 기본 shortlist는 연도별 2명이며 `.env`의 `AUTO_SHORTLIST_PER_YEAR`로 조정할 수 있습니다.
- 외부 세부자료가 없는 후보도 연·월·일·시 원국과 오행 계산을 재현할 수 있으면 TOP 10의 빈자리에 포함합니다. 화면에서는 이를 ‘원국 계산 완료’로 표시하고, 신강·용신처럼 외부 자료가 필요한 보조 항목은 임의로 채우지 않습니다. 동일 출생연도에서는 세부자료 확인 후보를 우선하되 최종 1명만 추천 순위에 들어갑니다.
- 그룹은 본인을 포함한 전체 인원 `n`에 대해 `n(n-1)/2`개의 관계를 계산합니다. 인원 상한은 두지 않습니다.

### 자동 추천 현실 연령 범위

- 24세 이하: 연상 5 / 연하 3
- 25~39세: 연상 8 / 연하 5
- 40~49세: 연상 10 / 연하 8
- 50세 이상: 연상 12 / 연하 10

## 캐시 정책

캐시는 다음 단계로 재사용합니다.

1. **사람 원국 캐시** — 같은 출생 조건이면 표시 이름과 무관하게 기존 원국 자료를 재사용합니다.
2. **원문 재파싱** — 파서가 개선되었거나 구조화 캐시에 빠진 항목이 있으면 기존 HTML/텍스트/네트워크 응답을 먼저 다시 읽습니다. 실제 일주가 있는 source-backed 캐시는 선택적 세부 항목이 비어 있어도 그대로 재사용하며, 자동으로 외부 브라우저를 다시 열지 않습니다.
3. **1:1 결과 캐시** — 동일 두 사람·동일 관계 모드·동일 계산 버전이면 결과를 재사용합니다.
4. **그룹 결과 캐시** — 동일 구성과 그룹 유형이면 관계행렬·역할·상세 결과를 재사용합니다.
5. **자동 추천 캐시** — 동일 사용자 조건과 계산 버전이면 검색 결과를 재사용합니다.

로컬 fallback처럼 외부 원국을 확인하지 못한 값은 source cache hit로 간주하지 않습니다. 반대로 외부에서 한 번 확인된 원국은 동일 출생 조건이면 이름이 달라도 재사용하고, 같은 요청 안의 중복 출생 조건도 1회만 확인합니다. 외부 강제 갱신은 명시적인 `force=True` 경로에서만 허용합니다.

## 운세 분리

올해·이번 달·오늘은 서로 다른 기간 간지와 서로 다른 생활 질문을 사용합니다.

- **올해**: 몇 달에 걸친 큰 방향과 기회·부담
- **이번 달**: 가까운 일정, 업무량, 지출, 관계 조율
- **오늘**: 당일 행동, 대화, 우선순위

문장 유사도가 과도하게 높으면 추가 외부 호출 없이 각 기간용 로컬 해설로 교체합니다. 대운은 원문에서 확인한 대운표의 시작 나이 기준으로 현재 구간을 선택합니다.

## 관계 해설 구조

### 1:1 / 자동 궁합

1. 나를 한눈에 보면
2. 상대를 한눈에 보면
3. 두 원국과 일주 조합
4. 잘 맞는 부분
5. 부딪히기 쉬운 장면
6. 나에게 맞는 소통법 / 상대에게 맞는 소통법
7. 역할·생활 분담
8. 장기적으로 맞출 부분
9. 접어 둔 명리 근거

일주 조합은 빠른 참고 정보이며 전체 궁합을 대신하지 않습니다.

### 그룹

- 관계도: 중요한 연결을 한눈에 탐색
- 관계 매트릭스: 모든 1:1 관계 확인
- 구성원별 역할: 그룹에서 자연스러운 역할과 주의점
- 두 사람 상세: 선택한 관계를 깊게 확인

관계도 노드는 이름, 생년월일, 한글 독음을 포함한 일주 정보를 제공합니다. 노드 hover는 개략 정보, 노드 클릭은 해당 구성원 중심 보기, 선/매트릭스 클릭은 두 사람 상세 Inspector로 연결됩니다. 빈 관계도 영역 또는 `선택 해제`로 언제든 전체 보기로 돌아갑니다.

## 진행률과 예상 시간

가짜 카운트다운을 사용하지 않습니다. 실제 작업 단계를 기반으로 진행률을 갱신하고, 최근 이 기기에서 측정한 실행시간을 이용해 예상시간을 보정합니다. `data/runtime_metrics.json`을 보존하면 반복 실행할수록 ETA가 현실적인 값으로 수렴합니다.

## 화면 디자인 기준

- 입력 헤더와 로딩 장면은 **토끼·무지개·구름·광원이 한 프레임에 합쳐진 8프레임 WebP**를 사용합니다. 토끼 PNG를 별도 사각형 레이어로 얹지 않습니다.
- 깡총 모션은 준비 → 상승 → 최고점 → 착지 → 작은 반동 순서로 반복하며, `prefers-reduced-motion`에서는 정적 JPG를 사용합니다.
- 페이지 바깥 배경은 viewport에 고정된 파스텔 그라데이션을 사용해 긴 그룹 목록을 스크롤해도 색이 끊기지 않습니다.

- 브랜드 토끼는 시작·로딩·브랜드 영역에만 사용하고 기능 정보는 일관된 SVG 아이콘으로 구분합니다.
- 본문은 긴 문장을 한 덩어리로 늘어놓지 않고 **키워드 → 굵은 소제목 → 1~3개의 짧은 문장 → 바로 적용할 행동** 순으로 보여줍니다.
- 전문용어·퍼센트·축별 점수는 기본 본문이 아니라 `명리 근거` 영역으로 한 단계 뒤에 배치합니다.
- 생활영역 카드는 선택해도 카드 그리드 높이가 변하지 않고, 상세 내용은 아래 전체폭 패널에 표시합니다.
- 그룹 관계도는 탐색 도구, Inspector는 설명 도구로 역할을 분리합니다. 노드/선/매트릭스는 같은 선택 상태를 공유하고 `선택 해제`로 즉시 전체 보기로 돌아갑니다.
- 데스크톱과 모바일 모두 텍스트가 잘리지 않도록 고정 본문 높이를 피하고 긴 이름·설명에는 안전한 줄바꿈을 적용합니다.

## 배포 전 확인

### 공개 체험 서비스 배포

저장소 루트의 `render.yaml`은 Render의 무료 단일 Docker 서비스용 설정입니다. 공개 체험 배포는 비용과 개인정보 노출을 막기 위해 다음 안전 모드로 시작합니다.

- `PUBLIC_DEPLOYMENT=1`: `/test`를 항상 404로 막고 동일 출처 JSON 요청만 허용합니다.
- `PERSIST_USER_DATA=0`: 이름·생년월일시·리포트를 서버 파일에 저장하지 않습니다.
- `EXTERNAL_SOURCE_ENABLED=0`, `AI_ENABLED=0`: 입력 정보를 외부 원국 서비스나 유료 AI로 보내지 않고 로컬 계산과 기본 해설만 사용합니다.
- `BUILD_AUTO_MATCHES=0`: 무료 인스턴스를 장시간 점유하는 TOP 10 전수 탐색은 공개 체험판에서 끄고, 내 사주·운세·1:1·그룹 궁합을 우선 제공합니다.
- 요청 크기·호출 빈도·그룹 최대 인원·동시 분석 수를 제한합니다.
- Gunicorn은 진행 상태가 한 프로세스 안에서 유지되도록 worker 1개와 thread 4개로 실행합니다.

Render에서 저장소를 Blueprint로 연결하면 `mongle-saju-report.onrender.com` 형식의 공개 URL이 발급됩니다. 무료 인스턴스는 일정 시간 사용이 없으면 잠들고 로컬 파일이 유지되지 않으므로, 외부 원국·AI·캐시 영속화를 운영하려면 유료 인스턴스와 영속 디스크, 개인정보 처리방침 및 비용 한도를 별도로 준비해야 합니다.

운영 상태 확인 경로는 `/healthz`입니다. 공개 사용자는 `/`만 사용하며 `/test`는 로컬 개발 전용입니다.

```bash
.venv-fourpillars-v3\Scripts\python.exe reparse_cache.py
.venv-fourpillars-v3\Scripts\python.exe verify_project.py
.venv-fourpillars-v3\Scripts\python.exe -m pytest -q
```

`verify_project.py`는 이미지/CSS/JS 누락, 중복 HTML id, 원국 표시 순서, 그룹 12명 제한 재유입, 직장 그룹의 연애 문구 분기, 신강·신약/대운 파서 계약, 기간 운세 분리, 캐시 완전성, 동적 윤달 입력, 그룹 선택/일주 상성 UI, 폐기된 함수 재유입, Python/JavaScript 문법을 검사합니다.

Playwright 수집까지 포함한 실제 브라우저 E2E는 외부 사이트 상태와 로컬 브라우저 의존성이 있으므로 최종적으로 `/test`에서 한 번 확인하는 것을 권장합니다.

## 사용자 중심 해설 원칙

기본 화면은 명리 용어와 퍼센트를 해석하도록 사용자에게 떠넘기지 않습니다.

- 개인 분석: **나는 어떤 사람인가 → 어떤 상황에서 강점이 살아나는가 → 어디서 피로해지는가 → 어떻게 활용할까**
- 1:1 연인 분석: **각자가 원하는 관계 → 잘 맞는 점 → 반복 갈등 → 소통 → 친밀감 → 동거/돈 → 배우자 역할 → 가족 경계 → 자녀운·양육 관점 → 갈등 회복 → 장기 체크**
- 직장 그룹: **각자의 업무 방식 → 잘 맞는 협업 → 충돌 장면 → 역할 분담 → 의사결정 → 피드백 규칙**
- 용신·십성·신강신약·축별 점수는 기본 결론 뒤의 `명리 근거`에서 확인합니다.

`자녀운·양육 관점`은 임신 가능성, 자녀 수, 성별을 예측하지 않습니다. 부모가 되었을 때의 훈육·교육·자율성·돌봄·역할 분담을 전통 명리의 참고 관점으로만 설명합니다.

## 포스텔러 원문 재사용과 진단

이미 저장된 `result.html`, `result.txt`, `network.json`이 있으면 브라우저를 다시 열기 전에 현재 파서로 재해석합니다. 현재 파서는 저장 HTML에서도 원국, 신강·신약, 용신, 신살·길성 위치, 대운을 복원합니다.

```bash
.venv-fourpillars-v3\Scripts\python.exe reparse_cache.py
.venv-fourpillars-v3\Scripts\python.exe diagnose_forceteller_cache.py
```

진단 결과에서 원문 marker는 존재하는데 parsed 값이 비어 있으면 파서 계약 오류로 취급해야 합니다. 브라우저 수집은 신강·신약/용신/대운 핵심 카드와 신살·길성 영역이 비동기로 렌더링될 시간을 기다린 뒤 전체 `page.content()`를 저장합니다.

## 캐시 재사용과 로컬 재생성

같은 출생정보를 반복 테스트할 때 UI/파서 수정만으로 OpenAI 비용이 다시 발생하지 않도록
AI 해설 캐시와 결정론적 결과 생성을 분리합니다. `/test`는 항상 AI cache-only 모드이며,
기존 해설이 없으면 로컬 fallback 문장만 사용합니다. 기존 v2 프로젝트의 `birth_date`,
`birth_time` 기반 manifest도 동일 출생정보로 정규화해 재사용합니다.

기존 프로젝트를 업그레이드한 뒤에는 다음을 한 번 실행하는 것을 권장합니다.

```bash
.venv-fourpillars-v3\Scripts\python.exe reparse_cache.py
.venv-fourpillars-v3\Scripts\python.exe diagnose_forceteller_cache.py
.venv-fourpillars-v3\Scripts\python.exe verify_project.py
.venv-fourpillars-v3\Scripts\python.exe -m pytest -q
```

현재 프로젝트와 형제 폴더의 `FourPillarsofDestiny*/data`를 자동 탐색하며, 별도 위치는
`.env`의 `LEGACY_DATA_DIRS`로 추가할 수 있습니다.
